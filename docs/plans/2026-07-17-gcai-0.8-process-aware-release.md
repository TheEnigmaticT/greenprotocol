# GC.ai 0.8 — Process-Aware Chemistry Analysis

**Date:** 2026-07-17  
**Source:** Seth’s technical-advisor recommendations, 2026-07-01  
**Status:** Release planning / backlog curation

## Release thesis

GC.ai should stop treating every protocol as the same kind of optimization problem. The next major release should make the user's process context explicit and let that context shape the analysis, retrieval, recommendation latitude, scorecard, and evidence presentation.

The release has two primary user modes:

### Discovery / R&D

Optimize the chemistry itself and the scientist's time:

- yield
- product purity
- elapsed process time
- number of operations / steps
- broader alternative transformations when evidence supports them

This mode may surface more exploratory candidates, including solvent-free, aqueous, mechanochemical, photochemical, or other alternative process concepts. These must be clearly labeled by evidence strength and uncertainty rather than presented as validated replacements.

### Development / scale-up

Optimize transferability, efficiency, safety, and business-relevant burden:

- hazardous waste
- process runtime
- energy burden
- safer substitutions and eliminations
- approximate hazardous-waste and energy cost proxies
- existing Green Chemistry scorecard metrics

This mode should be more constrained and auditable. Cost and LCA-like values are decision-support estimates only, with formulas, units, assumptions, and provenance visible.

## Procedure types

The first release should distinguish three process types:

1. **Reaction** — synthetic or biotransformation protocols.
2. **Formulation / material fabrication** — resins, coatings, membranes, pesticide formulations, and related material preparation.
3. **Separation / purification** — workup, isolation, purification, and solvent-intensive cleanup workflows.

The selection should be persisted with the analysis and passed into prompts, retrieval, scoring, recommendation guardrails, and UI labels. The first implementation should not attempt to build three unrelated products; it should establish a shared contract with type-specific rules and graceful unsupported states.

## Release pillars

### 1. Context foundation

- Context selection: Discovery / R&D or Development / scale-up.
- Procedure selection: Reaction, Formulation / Material Fabrication, or Separation / Purification.
- Persist both selections with each analysis.
- Show the active context prominently in results and exports.

### 2. Mode-specific scorecards

Keep the existing raw baseline visible. Add an inspectable profile layer:

- Discovery: yield, purity, time, and step count.
- Development: safety, waste, runtime, energy, cost proxies, plus current sustainability metrics.
- All metrics carry provenance: Declared, Calculated, Benchmark-derived, Model-inferred, or Unavailable.

Do not fabricate yield, purity, or cost values when the protocol lacks sufficient inputs.

### 3. Recommendations beyond substitution

Expand recommendations to include:

- removing auxiliary reagents or operations
- reducing equivalents
- eliminating transfers or purification burden
- reducing temperature or time
- route simplification
- evidence-backed alternative process concepts

Every recommendation must identify the affected step, expected benefit, risk/uncertainty, evidence state, and whether the claim is precedent, calculation, or model inference.

### 4. Evidence that supports adoption decisions

Evidence Atlas should show, next to each recommendation:

- evidence state
- number of supporting references
- structured paper/patent citations and links where available
- applicability caveats
- explicit model-inferred/no-direct-citation language when appropriate

Paywalls and missing evidence must be represented honestly, not hidden behind generic confidence language.

### 5. Practical input/output workflow

- Import procedures from PDFs, especially Supporting Information, with source page metadata and extraction review.
- Export the accepted revised procedure as readable text, preserving traceability to accepted recommendations and citations.
- Support goal-aware retrieval using a target substance or transformation as a bounded extension; do not include full autonomous retrosynthesis in 0.8.

## Existing backlog work to fold into 0.8

These existing items are aligned and should be treated as dependencies or implementation slices, not duplicated:

- Literature pipeline for citable recommendations.
- Literature-backed route optimization.
- Mechanochemistry alternatives.
- Two-pass retrieval re-evaluation.
- Standardized provenance taxonomy.
- Numeric PMI and provenance presentation.
- Assumed reaction-step decomposition before recommendations.
- Published process-redesign benchmark set.

Before dispatch, reconcile their current board states against the markdown source of truth and preserve only one canonical path for each.

## Recommended implementation sequence

### 0.8-A — Contract and context

1. Release brief review and scope lock.
2. Add persisted context/procedure-type fields.
3. Add context/type selection UI and safe defaults.
4. Thread context into pipeline and analysis metadata.

### 0.8-B — Evidence and scorecard foundation

5. Define mode-specific scorecard schema and provenance behavior.
6. Expose evidence counts/citations/model-inference labels.
7. Add missing-input and uncertainty states.
8. Add tests and representative analysis fixtures.

### 0.8-C — User-visible workflow value

9. Add elimination/process-simplification recommendation schema.
10. Add accepted revised-procedure export.
11. Add PDF protocol import and correction review.
12. Validate Discovery and Development flows separately.

### 0.8-D — Bounded advanced discovery

13. Add yield/purity/time precedent retrieval.
14. Fold mechanochemistry and route-precedent work into the Discovery retrieval contract.
15. Add bounded target-structure/reaction search only after the core context flow is stable.

## Explicit non-goals for 0.8

- Full autonomous retrosynthesis or route design.
- Guaranteed yield or purity prediction.
- Full LCA, TEA, regulatory, or legal/compliance claims.
- Full-fidelity support for every formulation/material process.
- Treating model-generated alternatives as experimentally validated.
- Reopening old canonical roots into repeated decomposition loops.

## Release acceptance bar

0.8 is ready for release review when:

- a user can run both Discovery and Development analyses;
- a user can select and see the procedure type;
- scorecard metrics change by mode without hiding baseline values;
- recommendations include substitutions and at least one elimination/simplification path;
- evidence counts, citations, provenance, and model-inference status are visible;
- PDF import and accepted-procedure export work on representative fixtures;
- results clearly separate reported precedent, calculation, estimate, and hypothesis;
- the release has separate validation examples for reaction, formulation/material, and separation/purification inputs;
- no major scope item remains in an ambiguous or recursively decomposed state.

# Evidence-backed chat actions — design

**Date:** 2026-08-12  
**Status:** Approved for planning

## Goal

Deliver the release’s two connected outcomes:

1. Make recommendations and chat retrieve page-bounded evidence from the parsed journal corpus rather than the currently empty article-level retrieval table.
2. Let a scientist use a recommendation-scoped chat to explicitly approve that exact recommendation by saying, for example, “approve this.”

Quality and scientific provenance outrank raw speed. The first streamed response should normally begin within 3 seconds.

## Existing state

- `literature_evidence_units` and `literature_source_documents` already model source document provenance, page ranges, candidate/adjudication state, limitations, and `text-embedding-3-small` vectors.
- Candidate evidence units are generated locally from canonical research-article text. Their status is `candidate_pending_adjudication`; they are retrieval seeds, not validated claims.
- `literature_precedents`, used by `lib/vector-search.ts`, has no remote rows. Its article-level shape cannot preserve the evidence-unit provenance required by this release.
- Scoped chat uses an immutable `TalkAboutContext` snapshot. Recommendation scope resolves to exactly one recommendation.
- Current chat tools are read-only and are executed server-side through the chemistry service.
- Existing approval writes `isAccepted` within a user-owned `gpc_analyses.analysis_result` document.

## Architecture

### Evidence import

Create a resumable, idempotent importer for the CRGSC corpus.

Inputs:

- Canonical article index.
- Candidate evidence-unit JSONL.
- Embedding JSONL generated by `embed_evidence_units_openai.py`.

The importer joins candidates and embeddings on `evidence_unit_id`, validates required provenance, then batch-upserts:

- `literature_source_documents` keyed by canonical document ID.
- `literature_evidence_units` keyed by evidence-unit ID.

Each imported unit must retain its DOI, title, source document ID, page range, quote, signal groups, candidate status, embedding model, embedding, and available applicability/limitations fields. The importer must reject incomplete or orphaned input rather than creating ambiguous evidence. A checkpoint/manifest records input checksums and inserted/upserted counts, enabling a safe rerun.

The importer operates on `literature_evidence_units`; it does not populate or depend on the obsolete article-level `literature_precedents` table.

### Recommendation evidence retrieval

Replace the old article-level `searchLiterature()` usage with evidence-unit retrieval. Embed the recommendation search query and call `match_literature_evidence_units`; attach citations that include source ID, title, DOI/URL when available, and page range. Recommendation re-evaluation receives page-bounded quotes and must preserve `candidate_pending_adjudication` rather than presenting a candidate as confirmed evidence.

### Scoped literature-search chat tool

Add `search_scoped_literature_evidence` to the existing server-side chat tool contract.

The model may supply a search question and optional signal-group filter, but the server constrains every request:

- Query is nonempty and at most 500 characters.
- Signal groups are drawn only from the controlled evidence vocabulary.
- Maximum five results.
- Chemical and procedure terms must resolve to the frozen conversation context; the tool rejects external/unscoped targets.
- Tool calls use the existing server-side embedding credential and Supabase RPC, never browser-supplied data or credentials.

The result returns only citation-ready, page-bounded material: source ID, title, DOI, page range, quote, similarity, candidate status, applicability, and limitations. It explicitly labels candidate evidence as candidate evidence. The route adds retrieved citation IDs to the persisted chat-message citation list and sends them in the terminal SSE event.

The chat model remains configured through the open-weights OpenAI-compatible provider. No proprietary fallback is introduced. SSE activity starts before retrieval completes; the first answer delta remains measured as `ttft_ms`.

### Scoped approval action

Add `approve_scoped_recommendation` as a server-owned chat action. It is an authorization action, not a chemistry-evidence tool.

Availability and target:

- It is available only when the immutable conversation scope is `kind: 'recommendation'`.
- It takes no recommendation ID, analysis ID, or user ID from the model or browser.
- The server derives its sole target from the immutable snapshot and validates that the snapshot contains exactly one recommendation.

Authorization and mutation:

- It may run only after an unambiguous current-message approval request.
- The route reloads the current analysis under the authenticated owner, resolves the snapshot’s exact recommendation, and sets only that recommendation’s `isAccepted` field to `true`.
- It is idempotent: an already-accepted recommendation succeeds without modifying unrelated data.
- The action must not support rejection, edits, substitutions, rescoring, or protocol mutation.

Audit and UI:

- Add an append-only `gpc_talk_actions` record for every requested/completed approval. It links conversation, analysis, user, action type, snapshot recommendation ID, status, and timestamps; it stores a minimal action receipt rather than mutable free text.
- On completion, the message route emits `recommendation-approved` with the immutable recommendation ID and display label.
- `TalkAboutThis` updates the bound analysis state/card and displays an in-chat receipt such as “Approved from this scoped conversation.”

## Error handling

- Import failure: fail the current batch with IDs and reason; preserve the prior checkpoint; do not publish a partial manifest as complete.
- Retrieval failure: report an unavailable tool result and continue chat; do not fabricate citations.
- No retrieval match: return an empty, explicitly no-match result; no source is cited.
- Approval scope mismatch, stale recommendation, missing analysis, or ownership failure: reject without mutation, append a failed action record where ownership permits, and stream an actionable error.
- Duplicate approval: return a successful idempotent receipt.

## Tests and verification

### Importer

- Idempotent source/evidence upsert.
- Resume after a partial output checkpoint.
- Missing embedding, missing source metadata, invalid page range, and orphan evidence fail before write.
- Imported row count and representative remote retrieval match the local manifest.

### Retrieval

- Maximum result count, input/signal validation, immutable-context scope enforcement, candidate-status preservation, citation attribution, and Supabase failure handling.
- Recommendation retrieval receives page-bounded evidence rather than article-only records.

### Approval

- Only recommendation scope may request an approval action.
- Approval changes only the one snapshot-bound recommendation in the current user-owned analysis.
- Cross-analysis, unscoped, stale, and unauthorized requests cannot write.
- Repeated approval is idempotent and produces a durable action receipt.
- The route’s SSE event updates the chat surface and recommendation card.

### Release smoke test

1. Import the selected corpus into the linked Supabase project.
2. Analyze a protocol whose recommendation can retrieve a known evidence unit.
3. Open that recommendation’s scoped chat, request a source-specific explanation, and observe a page-bounded, candidate-labelled citation.
4. Say “approve this”; observe the streamed approval receipt and persisted accepted recommendation after reload.
5. Measure first-token time on the chat path; investigate a normal path exceeding 3 seconds.

## Out of scope

- Importing the article-level `literature_precedents` table.
- Autonomous recommendation modification.
- Chat-driven rejection, substitution application, protocol edits, or rescoring.
- Treating candidate evidence as adjudicated evidence.
- A new proprietary-model fallback.
